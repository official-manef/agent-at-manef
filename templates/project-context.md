# Project context template

Label each item as verified, user-decided, proposed or unknown. Do not fabricate details to fill headings.

## Purpose and users
Problem, intended audience, desired outcome and original brief.

## Scope and exclusions
Included deliverables, boundaries and change-control process.

## Owners and stakeholders
Accountable role, decision-maker, collaborators and handoffs.

## Repository and branches
Verified URL, allowed branches, deprecated targets, concurrency/WIP rules.

## Architecture
Components, dependencies, data flow, storage and environments with source dates.

## Status and evidence
Separate source revision, tests, merge, deployment, live checks and acceptance.

## Access references
Provider/account owner, resource scope, private setup location and latest harmless read test. No values.

## Runbook
Inspect/build/test instructions, expected outputs, failure recovery and rollback.

## Backlog
Task references, owner, priority, dependencies and current blockers.

## Acceptance and risks
Definition of done, user-state coverage, privacy/security requirements and unresolved conflicts.

## Handover
What actually changed, evidence, preserved work and the next safe action.
