# Instruction files and canonical authority

[Architecture](architecture.md) · [Research](research.md)

| File | Role here | Not a substitute for |
|---|---|---|
| README.md | Human overview and navigation | Agent instructions or permissions |
| AGENT.md | Canonical mission, owner and working charter | Universal runtime discovery |
| AGENTS.md | Generated operating entrypoint and source references | Model or VM configuration |
| CLAUDE.md / GEMINI.md | Harness-specific views | Independently edited identity |
| SOUL.md | Selected runtime identity/behavior view | Authentication or actual memory persistence |
| SKILL.md | Task-specific procedure and discoverable metadata | Guaranteed tool availability |
| context.md / decisions | Curated facts, evidence, dates and uncertainties | Complete historical chat or live state |
| env.example | Empty configuration names | Actual account authorization |

[AGENTS.md](https://agents.md/) has no mandatory fields; each harness controls discovery and
precedence. Respect current task authority and host policy. This toolkit's singular AGENT.md
is intentionally a different canonical source, not a universal standard imposed on other apps.

[Agent Skills](https://agentskills.io/specification) supports metadata, instructions and optional
resources. Load relevant detail progressively. Our existing core exports Markdown, not complete
executable/assets bundles; extension requires its own validation, licensing and execution policy.

Read the selected charter, active project's complete relevant context and applicable procedures.
Record actual source paths and dates. Distinguish decisions, observations, proposals and conflicts.
Summarize long context with links and unread portions instead of claiming every source was read.
Update the canonical source through review, then regenerate views. Do not silently promote a
runtime's assumptions into permanent knowledge or overwrite edited output.
