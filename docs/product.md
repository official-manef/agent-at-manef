# Agent@Manef product brief

[README](../README.md) · [Research and critique](research.md) · [Library](library.md)

## Positioning

**One agent identity. Portable context. Deliberate migration.**

Agent@Manef helps people define agents, review existing setups, reconcile drift and recover
curated context on another platform. It is a Manef product created by Rahman. Upstream ownership,
product maintenance and the machine executing an agent are separate roles.

The intended audience is developers and technical teams managing agents across several tools.
Start with existing-agent cleanup and recoverable context rather than promising a replacement
for every chat app, VM host or orchestration service. MSO is a potential consumer, not a required
host. The toolkit remains local-first with explicit writes and no model/network dependency.

## Library can mean two products

The code library is a small versioned API/CLI for host applications; its source facade exists.
A catalog of agents/skills is a separate future distribution feature. Catalog entries need a
clear owner, license, provenance, content digest, version, required capabilities and review status.
Do not confuse discoverability with trust or install executable content without its own review.

## Priorities

First complete ownership transfer and canonical links, then release the tested local library.
Next select a small number of native targets for conformance and real destination acceptance.
Later add a reviewed agent/skill catalog, stronger backup provenance and optional encrypted
transport. Use MSO for operational UI/queues instead of embedding another scheduler here.

Success measures: recoverable context, migration effort, detected conflicts, preserved local
work, and completed evidence-backed acceptance. Adapter count and marketing claims are not
substitutes for those outcomes.
